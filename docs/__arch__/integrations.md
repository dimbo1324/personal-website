# Интеграции: Telegram и WhatsApp

Внутренний документ на русском языке. Описывает демо-контур, добавленный
2026-11-25 по прямому указанию владельца, и порядок вывода интеграций в бой.
Боевое подключение (шаг W5 плана) остаётся открытым: реальные ключи и номер
владелец ещё не передал.

## Зачем нужны заглушки

У сайта две независимые точки контакта с посетителем:

1. `POST /api/lead` — серверная Functions-функция: проверяет Origin, JSON,
   схему заявки, Turnstile и только после этого отправляет заявку в Telegram.
2. Форма «Оставить заявку» на странице — пока работает через Web3Forms или
   `mailto`;的真实 `/api/lead` к ней ещё не подключён.

Заглушки позволяют запустить и продемонстрировать оба контура без токенов,
секретов и реальной сети. Они **выключены по умолчанию** и включаются только
явными переменными окружения. Ни один режим не включает себя сам из-за опечатки
в названии переменной или значения.

## Серверный контур Telegram

| Переменная           | Значение по умолчанию | Что делает                                                  |
| -------------------- | --------------------- | ----------------------------------------------------------- |
| `LEAD_DELIVERY_MODE` | `telegram`            | `telegram` — реальная отправка; `stub` — демо-подтверждение |

Выбор происходит в `createLeadNotifier()` (`functions/lib/notifier.ts`):

- `TelegramNotifier` — существующий адаптер Telegram Bot API (`sendMessage`) с
  внедрённым `fetch`. При отсутствии токена, ошибке upstream, отказе API или
  сетевом сбое возвращает результат fail-closed — без успешного ответа.
- `StubLeadNotifier` — не делает сетевых вызовов и не сохраняет данные
  посетителя. Внутри только счётчик принятых вызовов. Возвращает
  `{ ok: true, mode: "stub" }`.

`LeadApiHandler` ожидает от нотификатора интерфейс `LeadNotifier` и не знает,
какой адаптер выбран. Успешный ответ Functions содержит поле
`delivery: "telegram" | "stub"` — по нему можно отличить демо от реальной
доставки. Ошибочные ответы по-прежнему содержат только стабильные коды
(`origin_not_allowed`, `turnstile_not_configured`, `telegram_not_configured`
и другие), без данных посетителя и текста ошибок upstream.

Важно: `stub` — это не «тихий успех». Он включается только явной настройкой и
виден и в ответе API, и в документации. В production переменную нужно удалить
или выставить значение `telegram`.

## Клиентский демо-режим формы

| Переменная         | Значение по умолчанию | Что делает                                         |
| ------------------ | --------------------- | -------------------------------------------------- |
| `PUBLIC_LEAD_MODE` | `live`                | `live` — штатный транспорт; `demo` — демо-доставка |

`resolveLeadMode()` (`src/scripts/site/config/env.ts`) принимает только явное
`demo` (регистр и пробелы не важны); всё остальное остаётся `live`. Из этого
значения `REQUEST_CONFIG` получает `transport: "demo"`, а `createGateway()`
возвращает `DemoGateway`.

`DemoGateway`:

- не вызывает `fetch`, не открывает почтовую программу, не пишет в хранилище;
- подтверждает валидную заявку текстом `form.result.demo` — «заявка проверена,
  но не отправлена»;
- подсказка у кнопки отправки заменяется на `form.hint.demo`, чтобы посетитель
  сразу видел, что это демо;
- черновик после отправки очищается, как и в штатном режиме.

Тексты добавлены на всех трёх языках (EN / ES / RU) в
`src/scripts/site/i18n/locales/`. Тест паритета ключей не даёт языкам разойтись.

## Канал WhatsApp

| Переменная              | Значение по умолчанию | Что делает                                       |
| ----------------------- | --------------------- | ------------------------------------------------ |
| `PUBLIC_WHATSAPP_PHONE` | номер из `CONTACT`    | телефон в любом формате; на выходе — цифры E.164 |
| `PUBLIC_WHATSAPP_MODE`  | `auto`                | `auto`, `real`, `stub`, `off`                    |

`WHATSAPP_CONFIG` (`src/scripts/site/data/whatsapp.ts`) собирает настройки,
`WhatsAppChannel` (`src/lib/whatsapp.ts`) превращает их в одно из двух
состояний:

- `{ kind: "link", href }` — настоящая ссылка `wa.me` с приветствием на языке
  посетителя;
- `{ kind: "placeholder", reason }` — честная заглушка без ссылки. Причина
  `stub` означает явный демо-режим, `unconfigured` — выключенный канал или
  некорректный номер.

Правила канала:

- `auto` — ссылка, если номер проходит проверку (8–15 цифр), иначе заглушка;
- `real` — только ссылка; при некорректном номере заглушка, а не «как будто
  работает»;
- `stub` — всегда заглушка с пометкой «демо-режим»;
- `off` — канал скрыт за заглушкой «не подключён».

`PhoneReveal` показывает ссылку с `target="_blank"` и
`rel="noopener noreferrer"` либо отключённую заглушку с `aria-disabled="true"`.
При смене языка обновляются и приветствие в ссылке, и текст заглушки.

## Локальная проверка

```bash
npm run test        # 41 файл, 167 тестов, включая все режимы заглушек
npm run gate        # полный гейт перед слиянием
```

Для ручной проверки демо-режима формы достаточно `PUBLIC_LEAD_MODE=demo` в
`.env` и `npm run dev`: подсказка у формы честно сообщает, что заявка никуда не
отправляется. Проверка серверного stub — `LEAD_DELIVERY_MODE=stub` в
`.dev.vars` и вызов `POST /api/lead` с валидным тестовым Turnstile-токеном; в
ответе будет `delivery: "stub"`.

## Вывод в бой (шаг W5)

1. Получить от владельца реальные ключи Turnstile, токен бота, ID чата и
   номер WhatsApp.
2. Удалить `LEAD_DELIVERY_MODE=stub` из окружения Functions — выставить
   `telegram` или убрать переменную вообще.
3. Убрать `PUBLIC_LEAD_MODE=demo` из сборки — оставить `live`.
4. Подключить форму к `/api/lead` вместо Web3Forms/`mailto` (отдельная задача).
5. Выставить `PUBLIC_WHATSAPP_MODE=real` и корректный
   `PUBLIC_WHATSAPP_PHONE`; проверить, что заглушка больше не появляется.
6. Запустить `npm run gate` и проверить живой вызов через Cloudflare Pages.

До выполнения этих шагов сайт находится в честном демо-контуре: либо штатный
`mailto`/Web3Forms, либо явно помеченное демо. Секреты в репозиторий не
попадают и в клиентский бандл не включаются.
